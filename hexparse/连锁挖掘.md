# 连锁挖掘法术（HexParse 文本）

本文给出三套可直接用 `/hexParse` 导入的连锁挖掘法术，全部只使用本整合包已有的图案（`get_caster`、`entity_pos/eye`、`get_entity_look`、`raycast`、`raycast/axis`、`for_each`、`add`、`sub`、`mul`、`break_block`）。

## 一、准备与使用

1. 主手拿一个 **Focus**（聚焦器）或任意可写 iota 的容器（法术书也行），执行：

   ```
   /hexParse "<代码>" "连锁挖掘"
   ```

   第二个参数是物品改名，可省略。代码中不能出现未转义的双引号，因此本文所有代码都不含字符串。

2. 把写好的 Focus 放到**副手**，主手拿法杖，画出：

   ```
   read
   eval
   ```

   `read` 会优先读取副手的物品，`eval` 执行读到的列表。也可以把代码页放进法术书直接施放。

3. **代码不要带最外层方括号。** hexparse 的顶层本身就是列表；写成 `[a,b,c]` 会多套一层列表，`read` + `eval` 只会把内层列表压进栈而不会执行它。上面的 `/hexParse read` 导出时也不会加外层括号。

## 二、3×3 平面连锁（9 格）

以准星命中的方块为中心，在水平面上挖掉 3×3。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
[add, break_block],
[vec_-1_0_-1, vec_0_0_-1, vec_1_0_-1,
 vec_-1_0_0,  vec_0_0_0,  vec_1_0_0,
 vec_-1_0_1,  vec_0_0_1,  vec_1_0_1],
for_each
```

原理：

- `get_caster` + `entity_pos/eye` 得到施法者眼睛坐标，再取一次施法者和 `get_entity_look` 得到视线向量；`raycast` 返回命中方块**中心**的 `vec`（未命中返回 `null`）。
- `for_each` 的参数顺序是「代码列表在前、数据列表在后」。每个偏移向量会被压到 `vec` 之上，`add` 求出绝对坐标，`break_block` 破坏该格。
- 偏移的 `y` 分量为 0，因此这是一个**世界坐标水平面**：看地面时在脚下挖一圈，看墙面时在墙面附近挖一圈。需要竖直方向时把偏移改成 `vec_0_-1_0` 等即可。

消耗：9 次 `break_block`（普通方块约 0.125 dust/格，`break_block` 的廉价方块约 0.01 dust/格）+ 1 次 `raycast`（0.01 dust）。

## 三、3×3×3 立方连锁（27 格）

把偏移扩成三层，一次挖出一个立方体。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
[add, break_block],
[vec_-1_-1_-1, vec_0_-1_-1, vec_1_-1_-1,
 vec_-1_-1_0,  vec_0_-1_0,  vec_1_-1_0,
 vec_-1_-1_1,  vec_0_-1_1,  vec_1_-1_1,

 vec_-1_0_-1,  vec_0_0_-1,  vec_1_0_-1,
 vec_-1_0_0,   vec_0_0_0,   vec_1_0_0,
 vec_-1_0_1,   vec_0_0_1,   vec_1_0_1,

 vec_-1_1_-1,  vec_0_1_-1,  vec_1_1_-1,
 vec_-1_1_0,   vec_0_1_0,   vec_1_1_0,
 vec_-1_1_1,   vec_0_1_1,   vec_1_1_1],
for_each
```

消耗：27 次 `break_block`，其余与上一节相同。注意 27 格必须全部落在默认 32 格编辑范围内。

## 四、直线钻探（沿命中面法线 8 格）

朝你瞄准的那个面往里钻一条 8 格深的一字隧道，适合挖矿脉、打竖直矿井。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast/axis,
[mul, sub, break_block],
[1, 2, 3, 4, 5, 6, 7, 8],
for_each
```

原理：

- 第一次 `raycast` 得到命中方块中心 `hitPos`。
- `raycast/axis` 得到命中面的**法线** `normal`（从方块指向你）。`hitPos - normal * k` 就是向方块内部第 k 格。
- 每个数据 `k` 被压栈后，`mul` 计算 `normal * k`，`sub` 计算 `hitPos - normal * k`，`break_block` 破坏该格。

调整深度：把 `[1, 2, 3, 4, 5, 6, 7, 8]` 加长或截短即可，最多到 32 格（默认 ambit）。

消耗：8 次 `break_block` + 2 次射线检测。

## 五、图案速查

| 图案 | 作用 |
| --- | --- |
| `get_caster` | 把施法者实体压栈 |
| `entity_pos/eye` | 实体 → 眼睛坐标 `vec` |
| `get_entity_look` | 实体 → 单位视线向量 `vec` |
| `raycast` | (起点, 方向) → 命中方块中心的 `vec`，未命中为 `null` |
| `raycast/axis` | (起点, 方向) → 命中面法线 `vec`，未命中为 `null` |
| `add` / `sub` / `mul` | 向量与向量 / 向量与数字的加减乘 |
| `for_each` | (代码列表, 数据列表) → 对每个数据执行一遍代码 |
| `break_block` | 破坏坐标处的方块 |
| `read` | 读取副手（或主手）可读物品中的 iota |
| `eval` | 执行栈顶的列表 |

## 六、注意事项

- **必须瞄准方块**。`raycast` 未命中会返回 `null`，`add`/`sub` 收到 `null` 会触发类型类 mishap，整个施法中断。
- 编辑范围受 `ambit_radius` 限制，默认 32 格；超出会触发 `MishapBadLocation`。
- 只有工具等级足够时才会掉落物品；石板等需要镐，徒手施法会破坏但不掉落。
- 基岩等 `destroySpeed < 0` 的方块不会被破坏，但对应 `break_block` 的媒介仍会照常扣除。
- 冒险模式或被领地保护的区域无法破坏方块。
- 每格都是独立结算，连锁会瞬间产生大量掉落物，注意实体数量和卡顿。
- 媒介单位：1 dust = 10000 media；普通方块 1/8 dust/格，廉价方块 1/100 dust/格。

## 七、hexParse 命令速查

| 命令 | 作用 |
| --- | --- |
| `/hexParse "<code>" [rename]` | 把文本解析成 iota 并写入手持的可写容器 |
| `/hexParse read` | 读取手持容器并把文本输出到聊天栏（可点击复制） |
| `/hexParse read_signatures` | 同上，图案只输出角度签名 |
| `/hexParse share` | 读取并向全服广播 |
| `/hexParse clipboard [rename]` | 用剪贴板原文导入 |
| `/hexParse clipboard_angles [rename]` | 只导入剪贴板中引号内的角度串 |
