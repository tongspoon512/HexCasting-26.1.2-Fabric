# 连锁挖掘法术（HexParse 文本）

本文给出三套可直接用 `/hexParse` 导入的连锁挖掘法术，全部只使用本整合包已有的图案（`get_caster`、`entity_pos/eye`、`get_entity_look`、`raycast`、`raycast/axis`、`for_each`、`add`、`sub`、`mul`、`break_block`）。

## 一、准备与使用

1. 主手拿一个 **Focus**（聚焦器）或任意可写 iota 的容器（法术书也行），执行：

   ```
   /hexParse "<代码>" "连锁挖掘"
   ```

   第二个参数是物品改名，可省略。代码中不能出现未转义的双引号，因此本文所有代码都不含字符串。

2. 把写好的 Focus 放到**副手**，主手拿法杖，画出：

   ```
   read
   eval
   ```

   `read` 会优先读取副手的物品，`eval` 执行读到的列表。也可以把代码页放进法术书直接施放。

3. **代码不要带最外层方括号。** hexparse 的顶层本身就是列表；写成 `[a,b,c]` 会多套一层列表，`read` + `eval` 只会把内层列表压进栈而不会执行它。上面的 `/hexParse read` 导出时也不会加外层括号。

4. **代码里的「代码列表 / 数据列表」必须用括号图案 `(` `)` 构造，不能写成 `[...]`。** `[` `]` 在 hexparse 里生成的是一个 ListIota 字面量；当它作为被 `eval` 的指令流中的一个元素出现时，会直接执行这个 iota，而 ListIota 不可执行，会触发 `MishapUnescapedValue` 让整场施法中断。`(` 是 Introspection、`)` 是 Retrospection，它们在**运行时**把中间的内容收成一个列表，这才是 `for_each` / `if` 想要的参数。本文所有列表参数都用 `(` `)`。

5. **要被「执行」的数字必须写成 `num_<n>` 图案。** hexparse 里裸数字（`0`、`1`、`2`…）解析成的是 `DoubleIota` **字面量**，只能当数据（如 `(1 2 3 4)` 这种数据列表）；一旦它落在被 `eval` 的指令位置上，就会报「本应运行一个图案，而实际运行了 1.00」（`MishapUnescapedValue`），整场施法中断。所以需要「先压入数字再运算」的地方必须用 `num_0` / `num_1` / `num_2` 这种图案，例如 `read/local, num_1, index`、`num_2, fisherman`。

## 二、3×3 平面连锁（9 格）

以准星命中的方块为中心，在水平面上挖掉 3×3。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
(add break_block),
(vec_-1_0_-1 vec_0_0_-1 vec_1_0_-1
 vec_-1_0_0  vec_0_0_0  vec_1_0_0
 vec_-1_0_1  vec_0_0_1  vec_1_0_1),
for_each
```

原理：

- `get_caster` + `entity_pos/eye` 得到施法者眼睛坐标，再取一次施法者和 `get_entity_look` 得到视线向量；`raycast` 返回命中方块**中心**的 `vec`（未命中返回 `null`）。
- `for_each` 的参数顺序是「代码列表在前、数据列表在后」。每个偏移向量会被压到 `vec` 之上，`add` 求出绝对坐标，`break_block` 破坏该格。
- 偏移的 `y` 分量为 0，因此这是一个**世界坐标水平面**：看地面时在脚下挖一圈，看墙面时在墙面附近挖一圈。需要竖直方向时把偏移改成 `vec_0_-1_0` 等即可。

消耗：9 次 `break_block`（普通方块约 0.125 dust/格，`break_block` 的廉价方块约 0.01 dust/格）+ 1 次 `raycast`（0.01 dust）。

## 三、3×3×3 立方连锁（27 格）

把偏移扩成三层，一次挖出一个立方体。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
(add break_block),
(vec_-1_-1_-1 vec_0_-1_-1 vec_1_-1_-1
 vec_-1_-1_0  vec_0_-1_0  vec_1_-1_0
 vec_-1_-1_1  vec_0_-1_1  vec_1_-1_1

 vec_-1_0_-1  vec_0_0_-1  vec_1_0_-1
 vec_-1_0_0   vec_0_0_0   vec_1_0_0
 vec_-1_0_1   vec_0_0_1   vec_1_0_1

 vec_-1_1_-1  vec_0_1_-1  vec_1_1_-1
 vec_-1_1_0   vec_0_1_0   vec_1_1_0
 vec_-1_1_1   vec_0_1_1   vec_1_1_1),
for_each
```

消耗：27 次 `break_block`，其余与上一节相同。注意 27 格必须全部落在默认 32 格编辑范围内。

## 四、直线钻探（沿命中面法线 8 格）

朝你瞄准的那个面往里钻一条 8 格深的一字隧道，适合挖矿脉、打竖直矿井。

```
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast,
get_caster,
entity_pos/eye,
get_caster,
get_entity_look,
raycast/axis,
(mul sub break_block),
(1 2 3 4 5 6 7 8),
for_each
```

原理：

- 第一次 `raycast` 得到命中方块中心 `hitPos`。
- `raycast/axis` 得到命中面的**法线** `normal`（从方块指向你）。`hitPos - normal * k` 就是向方块内部第 k 格。
- 每个数据 `k` 被压栈后，`mul` 计算 `normal * k`，`sub` 计算 `hitPos - normal * k`，`break_block` 破坏该格。

调整深度：把 `(1 2 3 4 5 6 7 8)` 加长或截短即可，最多到 32 格（默认 ambit）。

消耗：8 次 `break_block` + 2 次射线检测。

## 五、同种矿物连锁挖掘（渡鸦之思 quine）

前面三套是「无脑挖形状」，这一套是「只挖同种矿物、边挖边自动拾取、并且代码自引用」的版本。

### 5.1 原理

1. `raycast` 得到准星命中方块中心 `hit`。
2. MoreIotas 的 `type/to_item` 接收一个坐标 `vec`，返回该处方块的**方块类型 iota**（`ItemTypeIota`，只比较方块本体，忽略 blockstate）；坐标超出 ambit 时返回 `null`。
3. 把 `[T, L]` 写进**渡鸦之思**（`write/local`）：`T` 是目标矿物类型，`L` 是递归体。
4. 先破坏种子方块 `hit` 并拾取它的掉落物，再从渡鸦之思读回 `L` 并 `eval`，从 `hit` 开始泛洪。
5. `L(P)` 从渡鸦之思读回 `T`，枚举 P 周围 3×3×3 **去掉自身**的 26 个位置：`type/to_item(N)` 与 `T` 用 `equals` 比较，相同就 `break_block(N)`、拾取 N 附近的掉落物，再把 `N` 交给 `L` 自己（`read/local, num_1, index, eval`）。

拾取用 `zone_entity/item`（半径 1 收集掉落物实体）+ `for_each` + `pickup_item`（把掉落物收进物品栏）。

`break_block` 的破坏是立即生效的，被挖掉的格子变空气；空气的方块类型 ≠ `T`，所以泛洪会自然收敛。**没有 visited 集合**，终止条件就是你说的「op 运行次数耗尽」（默认 100000 次，触发 `MishapEvalTooMuch`，已经挖掉的方块保留）。

### 5.2 quine（自产生）

- `L` 在源码里只出现**一次**。
- 运行时把 `L` 本体作为 iota 存入渡鸦之思；递归时不再复制源码，只是 `read/local` 取回自身、`eval` 自身。
- 本 mod 做不到「文本 quine」（`string/parse` 只能解析 double，无法把字符串还原成代码），所以这里是**运行时自引用式 quine**：程序把自身作为数据保存，并从数据里重新执行自身。递归层数增加时也不会复制代码文本。

### 5.3 完整代码

```
get_caster, entity_pos/eye,
get_caster, get_entity_look,
raycast,
duplicate,
type/to_item,
singleton,
(
  read/local, num_0, index,
  (
    num_2, fisherman,
    add,
    duplicate, type/to_item,
    num_2, fisherman,
    equals,
    (
      duplicate, break_block,
      duplicate, (pickup_item), swap, num_1, zone_entity/item, for_each, mask_v,
      read/local, num_1, index, eval
    ),
    (),
    if, eval
  ),
  (
    vec_-1_-1_-1 vec_0_-1_-1 vec_1_-1_-1
    vec_-1_-1_0  vec_0_-1_0  vec_1_-1_0
    vec_-1_-1_1  vec_0_-1_1  vec_1_-1_1

    vec_-1_0_-1  vec_0_0_-1  vec_1_0_-1
    vec_-1_0_0               vec_1_0_0
    vec_-1_0_1   vec_0_0_1   vec_1_0_1

    vec_-1_1_-1  vec_0_1_-1  vec_1_1_-1
    vec_-1_1_0   vec_0_1_0   vec_1_1_0
    vec_-1_1_1   vec_0_1_1   vec_1_1_1
  ),
  for_each,
  mask_vvv
),
append,
write/local,
duplicate, break_block,
duplicate, (pickup_item), swap, num_1, zone_entity/item, for_each, mask_v,
read/local,
num_1, index,
eval
```

### 5.4 逐段栈变化

栈从左到右写，右边是栈顶。

**驱动段**

| 指令 | 栈 |
| --- | --- |
| `get_caster, entity_pos/eye, get_caster, get_entity_look, raycast` | `[hit]` |
| `duplicate, type/to_item` | `[hit, T]` |
| `singleton` | `[hit, [T]]` |
| 构造 `L`（中间那一大段括号） | `[hit, [T], L]` |
| `append` | `[hit, [T, L]]` |
| `write/local` | `[hit]`，渡鸦之思 = `[T, L]` |
| `duplicate, break_block` | `[hit]`，先破坏种子方块 |
| `duplicate, (pickup_item), swap, num_1, zone_entity/item, for_each, mask_v` | `[hit]`，拾取种子方块的掉落物 |
| `read/local, num_1, index` | `[hit, L]` |
| `eval` | 执行 `L(hit)` |

**递归体 `L`**（入口栈 `[P]`）

| 指令 | 栈 |
| --- | --- |
| `read/local, num_0, index` | `[P, T]` |
| 压入单轮代码 `K`、再压入 26 个偏移 | `[P, T, K, offsets]` |
| `for_each` | 每轮 `[P, T, o]`，结束时 `[P, T, <累积列表>]` |
| `mask_vvv` | 丢弃栈顶 3 个（P、T、累积列表）→ `[]` |

`L` 是**栈中性**的：吃掉传进来的 P，其它原样归还，所以递归不会让栈越堆越大。末端用 `mask_vvv`（Bookkeeper's Gambit 的 3 连弃，argc=3）清掉 `for_each` 固定会留下的累积列表。

**单轮 `K`**（每轮栈 `[P, T, o]`，o 是其中一个偏移）

| 指令 | 栈 |
| --- | --- |
| `num_2, fisherman` | `[T, o, P]`（把最深处的 P 提到栈顶） |
| `add` | `[T, N]`，N = P + o |
| `duplicate, type/to_item` | `[T, N, typeN]` |
| `num_2, fisherman` | `[N, typeN, T]` |
| `equals` | `[N, bool]` |
| 压入真分支、假分支 | `[N, bool, 真, 假]` |
| `if` | `[N, 选中分支]` |
| `eval` | 真分支留下 `[]`，假分支留下 `[N]`（两者都会进外层累积列表，最后被 `mask_vvv` 丢弃） |

真分支 `(duplicate, break_block, duplicate, (pickup_item), swap, num_1, zone_entity/item, for_each, mask_v, read/local, num_1, index, eval)`：

- `duplicate, break_block` 后剩 `[N]`，挖掉这一格。
- `duplicate` 再压一份 N，`(pickup_item)` 压入单条拾取代码，`swap` 把代码换到 N 下面，得到 `[N, K, N]`。
- `num_1` + `zone_entity/item` 收集 N 周围半径 1 内的掉落物，`for_each` 对每个掉落物执行 `K`（即 `pickup_item`）；`for_each` 会在栈上留一个累积列表，`mask_v` 丢掉它，回到 `[N]`。
- `read/local, num_1, index` 得 `L`，`eval` 让 `L` 吃掉 N 递归下去（返回 `[]`）。

假分支 `()` 是空列表，`eval` 什么也不做，只留 `[N]` 进外层累积列表。

### 5.5 调整

- **3×3 平面版**：删掉 y=±1 的 18 个偏移，只留 y=0 那 8 个。
- **更大范围**：把偏移扩到 -2..2（124 个），op 消耗线性增长，注意 ambit 与媒体。
- **保留种子方块**：删掉驱动里那对 `duplicate, break_block` 和紧随的拾取段，并把 `vec_0_0_0` 加回偏移列表。代价是每个方块会被多递归一次（因为「自己」那一格又会触发一遍）。
- **同时挖多种矿物**：在 K 的 `equals` 后面用 `or` 串上第二组「另一个 T 的比较」，需要存第二个类型。
- **关闭自动拾取**：删掉驱动末尾和真分支里的 `duplicate, (pickup_item), swap, num_1, zone_entity/item, for_each, mask_v` 两段即可（掉落物留在原地，能挖的格数会稍多）。
- **调整拾取半径**：把两处 `num_1` 改成 `num_0.5` 更保守（只收本格掉落的物品），改成 `num_2` 会连附近别人掉的物品一起收走。

### 5.6 注意

- **必须瞄准方块**。`raycast` 未命中返回 `null`，`type/to_item` 收到 `null` 会立刻类型类 mishap。
- `type/to_item` 对超出 ambit 的坐标返回 `null`（不 mishap），`equals(null, T)` 为假，因此边界格子是安全的。
- `break_block` 会做 `assertPosInRangeForEditing`（含编辑权限检查）；出生点保护、领地等会让它 mishap 并中断整场施法。
- 依赖 MoreIotas 的 `type/to_item` 运算（extract_item）；服务器若禁用该运算则整套失效。
- 拾取依赖 `pickup_item`（拾取掉落物实体）与 `zone_entity/item`（范围内掉落物列表）：每挖一格多做一次球形检索和一次 `for_each`（`duplicate`、`(`、`)`、`swap`、`num_1`、`zone_entity/item`、`for_each`、`mask_v` 共 8 op），外加上每件掉落物 1 op。
- `pickup_item` 等同于玩家自己走过去捡：会清掉掉落物的拾取延迟并把物品直接进背包；它只接受**掉落物实体**，箱子里的物品或被生物持有的物品不算；施法者必须是玩家（非玩家环境会触发 `MishapBadCaster`）。
- `zone_entity/item` 会把半径内的**所有**掉落物收走（包括不是这次挖出来的）。只想捡本格的掉落物就把半径调小；拾取段对已消失的实体只会跳过，不会 mishap。
- 预算：约 18 op × 26 邻居 ≈ 470 op/方块，默认 100000 op 大约能挖 180～210 格；把 `maxOpCount` 调大可以挖更长的矿脉。
- 渡鸦之思在施法结束时清空，所以每次都要重新施放整段；它只在本场施法里起「自我保存」作用。

### 5.7 新增图案

| 图案 | 作用 |
| --- | --- |
| `type/to_item` | MoreIotas：坐标 → 该处方块类型 iota（超范围给 `null`） |
| `zone_entity/item` | (中心 vec, 半径) → 半径内掉落物实体列表 |
| `pickup_item` | 拾取：把掉落物实体 iota 代表的那件掉落物收进施法者背包 |
| `singleton` | 一个 iota → 只含它的列表 |
| `append` | (列表, iota) → 追加后的列表 |
| `equals` | 两个 iota 容差比较 → bool |
| `if` | (条件, 真值, 假值) → 选中那个 |
| `read/local` / `write/local` | 读/写渡鸦之思（Raven's Mind） |
| `mask_vvv` | Bookkeeper's Gambit：丢弃栈顶 3 个 iota |
| `fisherman` | 按深度把栈里某个 iota 提到栈顶（**会移除原位置**） |
| `num_<n>` | 数字字面量的**图案**形式，执行时压入该数字（裸数字 `n` 是字面量，不能被执行） |

## 七、注意事项

- **必须瞄准方块**。`raycast` 未命中会返回 `null`，`add`/`sub` 收到 `null` 会触发类型类 mishap，整个施法中断。
- 编辑范围受 `ambit_radius` 限制，默认 32 格；超出会触发 `MishapBadLocation`。
- 只有工具等级足够时才会掉落物品；石板等需要镐，徒手施法会破坏但不掉落。
- 基岩等 `destroySpeed < 0` 的方块不会被破坏，但对应 `break_block` 的媒介仍会照常扣除。
- 冒险模式或被领地保护的区域无法破坏方块。
- 每格都是独立结算，连锁会瞬间产生大量掉落物，注意实体数量和卡顿。
- 媒介单位：1 dust = 10000 media；普通方块 1/8 dust/格，廉价方块 1/100 dust/格。

## 八、hexParse 命令速查

| 命令 | 作用 |
| --- | --- |
| `/hexParse "<code>" [rename]` | 把文本解析成 iota 并写入手持的可写容器 |
| `/hexParse read` | 读取手持容器并把文本输出到聊天栏（可点击复制） |
| `/hexParse read_signatures` | 同上，图案只输出角度签名 |
| `/hexParse share` | 读取并向全服广播 |
| `/hexParse clipboard [rename]` | 用剪贴板原文导入 |
| `/hexParse clipboard_angles [rename]` | 只导入剪贴板中引号内的角度串 |
