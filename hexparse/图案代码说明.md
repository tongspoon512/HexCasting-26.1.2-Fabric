# 图案代码说明

本文说明法术图案的「代码」是怎么写的、怎么读的，以及这些代码最终被画成什么样子。文中只涉及图案本身的几何与绘制方式，不涉及其它实现细节。

## 一、图案代码是什么

一个图案就是六边形网格上的一笔画折线。它的代码是一串字母，记录画笔**每一步怎么拐弯**，例如：

- `qaq`
- `aa`
- `dewqaedwawadadawa`

代码不含起点位置，也不含起始朝向——它只描述「从落笔开始，沿路怎么转」。因此同一串代码可以画在网格的任何地方。

每段线都一样长：从当前格点沿当前方向走到相邻格点，就是一格。

## 二、网格与方向

图案画在六边形网格上，每个格点有六个相邻方向：

| 方向 | 简称 | 坐标增量 (x, y) |
| --- | --- | --- |
| 东北 | NE | (1, -1) |
| 东 | E | (1, 0) |
| 东南 | SE | (0, 1) |
| 西南 | SW | (-1, 1) |
| 西 | W | (-1, 0) |
| 西北 | NW | (0, -1) |

坐标以「向右为 x 正、向下为 y 正」绘制。相邻方向之间相差 60°，因此所有转角都是 60° 的整数倍。

## 三、六个转角字母

| 字母 | 含义 | 转角（顺时针为正） |
| --- | --- | --- |
| `w` | 直行 | 0° |
| `e` | 右转 | 60° |
| `d` | 右转 | 120° |
| `s` | 掉头 | 180° |
| `a` | 左转 | 120° |
| `q` | 左转 | 60° |

其中 `s`（掉头）在合法图案中不会出现：它会让画笔立刻沿刚才那段线走回去。

## 四、起始方向

代码串本身不包含起始方向。绘制时先确定「第一段朝哪」，之后每个字母只改变方向。

- 在游戏里画图案时，第一段的方向由你落笔后的第一划决定。
- 书页、速查表等静态展示会为每个图案指定一个**规范起始方向**（常见是东或东北），保证同一个图案每次都被画成相同的朝向。
- 由于代码只记录转角，起点平移或整体转向都不改变代码本身；规范起始方向只影响展示时的摆法。

## 五、如何读一串图案代码

读法固定为「先走一段，再拐弯」：

1. 把笔放在起点，朝向起始方向。
2. 沿当前方向走一格。
3. 读一个字母，按上表转向。
4. 重复第 2、3 步，直到字母读完。
5. 最后一个字母转完方向后，再沿当前方向走一格收尾。

因此：**字母数 + 1 = 线段数**。两个字母的图案由三段线组成，三个字母的图案由四段线组成。

### 例子：`aa`，起始方向为东

| 步骤 | 进入时的方向 | 做的事 | 到达格点 |
| --- | --- | --- | --- |
| 起点 | 东 | — | (0, 0) |
| 第 1 段 | 东 | 走一格，读 `a`，左转 120° | (1, 0) |
| 第 2 段 | 西北 | 走一格，读 `a`，左转 120° | (1, -1) |
| 第 3 段 | 西南 | 走一格收尾，不再转向 | (0, 0) |

三条边首尾相接，回到起点，画出一个闭合三角形。

### 例子：`qaq`，起始方向为东北

依次走过 (0, 0) → (1, -1) → (1, -2) → (0, -1) → (0, 0)，是一条四段折线：先向东北，左转 60° 向西北，再左转 120° 向西南，再左转 60° 向东南，最后回到起点，围成一个闭合菱形。

## 六、什么样的代码是合法的

- **不能掉头**：不能出现 `s`。
- **不能压线**：任何一段线都不能与已经画过的线重合，正向、反向都不行。
- **可以回到旧点**：回到之前经过的格点是允许的（闭合图案就是如此），只要不共用已有的边。

这些限制同时保证了图案能被稳定识别，也保证了渲染时线条不会互相盖住、糊成一团。

## 七、图案是怎么画出来的

同一串代码，无论在书页、施法网格还是方块表面上，轮廓都完全一致；不同的只是尺寸、线宽、颜色与动画。绘制时主要包含这些部分：

### 1. 格点与起点

- 折线经过的每个格点都会画一个小圆点。
- 起点用醒目的蓝色圆点标记，其余格点用半透明的浅灰圆点。
- 格点可以关闭；开启「显示笔画顺序」时会连同格点一起显示，便于对照代码阅读方向。

### 2. 双层描边

折线由两层叠成：

- 外层更宽，构成轮廓与外侧光晕；
- 内层更窄，叠在外层上方，是图案的主要颜色。

两层叠加让线条看起来有厚度和微微的发光感。线宽与圆点半径会跟随图案的整体缩放一起变化，因此放大或缩小图案时比例保持协调。

### 3. 电脉冲式的微小抖动

折线并不是死板的直线。绘制时会沿路径叠加细小的偏移，形成类似电流在笔画里跳动的效果：

- 静止的图案抖动幅度小，线条基本保持原形；
- 有动画的图案（例如正在充能的法术环）抖动更明显，并带有流动感；
- 「可读」模式会在自交形成的重复格点处把线头稍微收进来，并让最后一段略短，避免重叠处糊成色块。

这些抖动只影响观感，不改变图案的几何形状，也不影响图案代码。

### 4. 颜色

颜色是绘制时传入的参数，不写在图案代码里，因此同一个图案可以按场景换色：

- 默认是沿笔画由深到浅的灰白渐变；
- 暗淡状态使用整体压暗的灰白；
- 充能状态使用提亮的蓝色或紫色，并加强光晕；
- 起始点圆点保持蓝色，用来提示「从哪里起笔」。

### 5. 纹理与逐帧绘制

- 静止且颜色单一的图案会预先烘焙成纹理，之后直接贴图复用，因此大量图案同时显示时也不容易卡顿。
- 正在移动、带流动动画或带渐变色的图案无法用固定纹理表示，会逐帧重新绘制线条。

对使用者来说两者外观一致，区别只在于性能与动画。

### 6. 尺寸与摆放

图案会按可用空间等比缩放，并在给定区域内居中；线宽、圆点大小、留白都由展示场景决定。因此同一个图案在书页里可能是小图标，在法术环上则可能很大，但折线的形状和转角完全相同。

## 八、用其它方式实现图案绘制（HTML、Android 等）

这一节面向没接触过本项目的开发者：图案的观感完全由矢量几何和少量绘制参数决定，不依赖任何原始贴图。只要按下面的步骤，就能在网页、Android、桌面或任何 2D 绘图 API 上还原同样的效果。

### 1. 需要的输入

- 图案代码，例如 `qaq`；
- 起始方向，用 0..5 表示：东北、东、东南、西南、西、西北（常用东 = 1）；
- 目标区域尺寸、线宽与配色。

线宽可以按尺寸取固定比例。下文用 `S` 表示外层线宽。

### 2. 代码换算成格点坐标

方向与第二节相同，用 `(q, r)` 记录格点：

| 序号 | 方向 | 增量 (Δq, Δr) |
| --- | --- | --- |
| 0 | 东北 | (1, -1) |
| 1 | 东 | (1, 0) |
| 2 | 东南 | (0, 1) |
| 3 | 西南 | (-1, 1) |
| 4 | 西 | (-1, 0) |
| 5 | 西北 | (0, -1) |

格点转屏幕坐标（`size` 是网格缩放，所有线段长度都会等于 `√3 · size`）：

```text
x = √3 · q + (√3 / 2) · r
y = 1.5 · r
```

完整换算（JavaScript，可直接放到浏览器控制台）：

```js
const S3 = Math.sqrt(3);
const STEP = [[1, -1], [1, 0], [0, 1], [-1, 1], [-1, 0], [0, -1]]; // NE,E,SE,SW,W,NW
const TURN = { w: 0, e: 1, d: 2, s: 3, a: 4, q: 5 };               // 60° 的倍数

// 代码 -> 格点数组；长度恒为「字母数 + 2」
function hexPoints(code, startDir = 1) {
  let dir = startDir, q = 0, r = 0;
  const pts = [[q, r]];
  for (const ch of code) {
    q += STEP[dir][0];
    r += STEP[dir][1];
    pts.push([q, r]);
    dir = (dir + TURN[ch]) % 6;
  }
  q += STEP[dir][0];
  r += STEP[dir][1];
  pts.push([q, r]);   // 最后一个字母之后沿最终方向收尾
  return pts;
}

// 格点 -> 像素
const toPixel = ([q, r], size) => [S3 * (q + r / 2) * size, 1.5 * r * size];
```

注意数组比字母数多 2：第一个是起点，最后一次 `push` 是收尾段。游戏内渲染包含这段收尾线，复刻时不要省略。

### 3. 等比缩放并居中

算出所有点的包围盒，取 x、y 两个方向所需缩放中较小的一个，保证不变形；留白要包含半个线宽，避免粗线被裁掉：

```js
function fitToBox(pts, width, height, pad) {
  const xs = pts.map(p => p[0]), ys = pts.map(p => p[1]);
  const minX = Math.min(...xs), maxX = Math.max(...xs);
  const minY = Math.min(...ys), maxY = Math.max(...ys);
  const scale = Math.min((width - 2 * pad) / Math.max(maxX - minX, 1e-6),
                         (height - 2 * pad) / Math.max(maxY - minY, 1e-6));
  const cx = (minX + maxX) / 2, cy = (minY + maxY) / 2;
  return pts.map(([x, y]) => [width / 2 + (x - cx) * scale, height / 2 + (y - cy) * scale]);
}
```

### 4. 绘制顺序与比例

按「外层 → 内层 → 起点圆点 → 其余格点」的顺序绘制：

| 元素 | 尺寸 | 默认颜色 |
| --- | --- | --- |
| 外层折线 | 线宽 `S` | 沿笔画从 `#554d54` 渐变到 `#d2c8c8` |
| 内层折线 | 线宽 `0.4·S` | 同上（两层默认同色） |
| 起点圆点 | 半径 `0.32·S` | `#5b7bd7` |
| 其余格点 | 半径 `0.16·S` | `#d2c8c8`，透明度约 50% |

- 折线用圆角连接与圆头端点，避免尖角；若平台不支持圆角，可把每个折点补一个半径 `S/2` 的小圆来模拟。
- 两层默认同色，叠起来就是一条带渐变的粗线；把内层换成更亮的颜色（如充能时的蓝紫色），就能得到发光的芯。
- 渐变方向是沿笔画从起点到终点。若首尾重合（如 `aa` 的闭合三角形），这条线长度为 0，无法作为渐变轴，可改用包围盒对角线，或直接使用纯色。
- 填充半透明颜色时要注意两层与折点会互相叠加；需要透明效果时，建议先画一层不透明底色，或把相邻线段合并成一条路径一次画完。

一个最小的 Canvas 版本：

```js
function drawPattern(ctx, code, { size = 256, startDir = 1, stroke = size / 12 } = {}) {
  const pts = fitToBox(hexPoints(code, startDir).map(p => toPixel(p, 1)), size, size, stroke);

  const path = new Path2D();
  path.moveTo(...pts[0]);
  for (const p of pts.slice(1)) path.lineTo(...p);

  // 闭合图案首尾重合时渐变轴长度为 0，改用离起点最远的点
  const [x0, y0] = pts[0];
  const last = pts[pts.length - 1];
  const closed = last[0] === x0 && last[1] === y0;
  const target = closed
    ? pts.reduce((a, b) =>
        Math.hypot(b[0] - x0, b[1] - y0) > Math.hypot(a[0] - x0, a[1] - y0) ? b : a, pts[0])
    : last;
  const grad = ctx.createLinearGradient(x0, y0, target[0], target[1]);
  grad.addColorStop(0, '#554d54');
  grad.addColorStop(1, '#d2c8c8');

  ctx.lineJoin = ctx.lineCap = 'round';
  ctx.strokeStyle = grad;

  ctx.lineWidth = stroke;        // 外层
  ctx.stroke(path);
  ctx.lineWidth = stroke * 0.4;  // 内层
  ctx.stroke(path);

  const dot = ([x, y], r) => {
    ctx.beginPath();
    ctx.arc(x, y, r, 0, Math.PI * 2);
    ctx.fill();
  };

  ctx.fillStyle = '#5b7bd7';
  dot(pts[0], stroke * 0.32);
  ctx.fillStyle = 'rgba(210, 200, 200, 0.5)';
  for (const p of pts.slice(1)) dot(p, stroke * 0.16);
}
```

### 5. 可选的电流抖动

静态展示可以完全不做抖动；需要动画时，把每一段线细分成 `hops` 份，对中间的点加一个小偏移：

```text
每段长度 L，hop = L / hops
对第 j 个中间点（1 ≤ j < hops）：
  t = j / hops
  taper(t) = min(1, 8 × (0.5 - |0.5 - t|))   // 两端为 0，中间最大
  offset = noise(段序号, j, 时间) × hop × variance × taper(t)
  方向随机，把该点沿垂直/任意方向偏移 offset
```

- `taper` 保证段的两个端点不动，只在中间抖动，因此折点仍然准确。
- 用带种子的二维或三维噪声即可；关键是同一段、同一时刻的偏移要稳定，随时间缓慢变化就形成流动感。

常用参数：

| 用途 | hops | variance | speed | 说明 |
| --- | --- | --- | --- | --- |
| 静态展示 | 10 | 0.5 | 0 | 抖动很小，形状基本不变 |
| 可读模式 | 10 | 0.5 | 0 | 自交处收线头、末段缩到 80% |
| 法术环/充能 | 10 | 2.5 | 0.1 | 抖动明显，并随时间流动 |

格点圆点始终画在精确的格点位置上，不参与抖动。

### 6. 各平台对应的绘制接口

| 能力 | HTML Canvas | SVG | Android Canvas |
| --- | --- | --- | --- |
| 折线 | `beginPath` + `moveTo`/`lineTo` + `stroke` | `<polyline points="...">` | `Path` + `Canvas.drawPath`，`Paint.Style.STROKE` |
| 圆角 | `lineJoin`/`lineCap = "round"` | `stroke-linejoin`/`stroke-linecap="round"` | `StrokeJoin.ROUND` / `StrokeCap.ROUND` |
| 渐变 | `createLinearGradient` | `<linearGradient gradientUnits="userSpaceOnUse">` | `LinearGradient` + `Paint.setShader` |
| 圆点 | `arc` + `fill` | `<circle>` | `Canvas.drawCircle` |

### 7. 缓存

- 静止且纯色的图案，可以按「代码 + 起始方向 + 尺寸 + 配色」把结果画到离屏画布/位图里缓存，之后直接复用。
- 带动画或渐变的图案逐帧绘制；若只是渐变但不动，可以先把渐变烘焙进缓存。
- 同一串代码在不同尺寸下需要不同的缓存，因为线宽与点半径是相对 `S` 计算的。

### 8. 自检清单

- 线段数等于「字母数 + 1」，点数为「字母数 + 2」。
- 起点蓝点在数组第一个点上；其余格点半透明。
- `aa`（起始方向东）应闭合成三角形；`qaq`（起始方向东北）应是四段闭合菱形。
- 外层 : 内层线宽 = 1 : 0.4；起点 : 格点半径 = 0.32 : 0.16。
- 出现 `s`、压线或首尾重叠的边时，说明代码本身不合法。

## 九、自己写图案时的建议

1. **先画后抄**：在网格上画出想要的形状，再从起点开始逐段记录「直行 / 左转 60° / 右转 120°……」。
2. **不要出现 `s`**，也不要把线画到已有线段上。
3. **想清楚规范起始方向**：代码本身与方向无关，但书页展示需要一个固定朝向，建议选一个能一眼看出形状的方向。
4. **避免与已有图案撞码**：转角序列相同就是同一个图案；平移不会改变代码，镜像则会把左右转互换、得到另一串代码，属于另一个图案。

已有的图案及其代码可以在 [图案 id 速查表](图案id速查表.md) 中按名称查找；表中同时给出了对应的完整 id，便于对照。
