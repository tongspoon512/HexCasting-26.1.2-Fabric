# 卓越哨卫 8×1×8 矿石挖掘（磁带 quine）

## 原理

- 磁带 quine 模板每周期把自身再次入队（`num_20` = 20 tick，约 1 秒），所以咒术会自动重复施放。
- 载荷插在模板的空代码块中：

```text
...,add,(,<载荷>,),eval,num_20,hexcassettes:enqueue,),duplicate,eval
```

  执行载荷时栈上只有本轮要入队的 `C'`，因此载荷必须净零出入。
- 不用 `for_each`：它会把每一轮执行完的整个栈追加进累加列表；`C'` 会被复制 64 次，超过 1024 个 iota 的序列化上限，直接触发栈过大 mishap。
- 改用**递归 eval**：递归体 `P` 自己作为数据留在栈上，每轮从剩余偏移列表中取一个、处理完后再 `eval` 一次 `P`。栈始终保持

```text
[C', P, pos, 剩余偏移列表]
```

  大小约 300 个 iota（含拾取循环体），远低于上限。
- 每个周期依次做四件事：
  1. **确保哨卫并取坐标**：无哨卫就按施法者脚底建一个卓越哨卫；然后 `sentinel/get_pos` 取当前坐标 `pos`。
  2. **扫描一层**：以 `pos` 为原点，扫描 `x ∈ [-4, 3]`、`y = 0`、`z ∈ [-4, 3]`（即哨卫所在层），命中名称含“矿石”的方块就 `break_block`。
  3. **拾取**：方块被破坏后，用 `zone_entity/item`（半径 2）列出该处附近全部掉落物，再逐个 `pickup_item`，直到列表清空。
  4. **哨卫步进**：以 `pos + (0,-1,0)` 重建卓越哨卫（覆盖旧哨卫），于是下一周期以降低一层的坐标为扫描中心。

## 拾取为什么会漏（原因定位）

**结论：主要是咒术列表的取物方式；模组本体没有问题。**

- **模组侧**：`pickup_item`（`OpPickupItem`）的 `argc = 1`，一次只处理**一个** `ItemEntity` iota；`Spell.cast` 只调用一次 `ItemEntity.playerTouch`，即原版拾取逻辑——背包放不下时本来就不会全部入包。这是刻意设计，不是 bug。
- **咒术侧（主因一）**：旧版每格只调用一次 `get_entity/item`，而它**只返回查询框内距离最近的一个**实体。一个方块即便掉出多堆物品，也只拾起一堆，其余留在原地；现有的地面掉落物还会被“顺手”抢占这个唯一的拾取名额。
- **咒术侧（主因二）**：`get_entity/item` 的查询框是**以 `target` 为中心的 1×1×1 立方体**，而 `target = 哨卫脚底坐标 + 整数偏移`，并不是方块中心。脚底 `y` 为整数时，方块中心在 `y + 0.5`，掉落物的包围盒下沿恰好压在查询框上边界；AABB 相交用的是严格不等式，边界重合会被判为**不相交**，于是这部分掉落物根本查不到。掉落物生成时带随机位移，只有“略低一点”的那些能落进框内——这正好对应“拾取了一部分、但不是全部”的观察结果。

修复办法：不再用 `get_entity/item`，改为 `zone_entity/item`（半径 2）一次性取出该处的所有掉落物，再对列表做一次递归遍历（每轮 `deconstruct` + `pickup_item`），逐个拾取。列表遍历而不是“反复查询直到查空”，可以避免背包满时同一物品反复被查到、导致死循环。

## 扫描范围

- 以**当前哨卫坐标**为原点，`x ∈ [-4, 3]`、`y = 0`、`z ∈ [-4, 3]`，共 **64** 格（8×1×8）。
- `y = 0` 表示与哨卫同层；哨卫每周期下降一格，所以实际扫描层依次为初始脚底 `y`、`y-1`、`y-2`……
- 层内 `x/z` 偏移不变，只是原点跟着哨卫下移。
- 只处理本地化名称中含“矿石”的方块：`type/to_item` 取方块 → `string/iota` 取名称 → `index_of` 查子串 → `greater_eq 0` 判存在。

## 递归体注释版（仅供阅读/修改，注释会被 hexparse 忽略）

```text
// ── A. 确保卓越哨卫，并取哨卫坐标           栈：C' → C', pos
sentinel/get_pos, const/null, type_equals,
( get_caster entity_pos/foot sentinel/create/great ), ( ), if, eval,
sentinel/get_pos,

// ── B. 压入 8×1×8 偏移表与递归体 P
( vec_-4_0_-4, vec_-4_0_-3, vec_-4_0_-2, vec_-4_0_-1, vec_-4_0_0, vec_-4_0_1, vec_-4_0_2, vec_-4_0_3, vec_-3_0_-4, vec_-3_0_-3, vec_-3_0_-2, vec_-3_0_-1, vec_-3_0_0, vec_-3_0_1, vec_-3_0_2, vec_-3_0_3, vec_-2_0_-4, vec_-2_0_-3, vec_-2_0_-2, vec_-2_0_-1, vec_-2_0_0, vec_-2_0_1, vec_-2_0_2, vec_-2_0_3, vec_-1_0_-4, vec_-1_0_-3, vec_-1_0_-2, vec_-1_0_-1, vec_-1_0_0, vec_-1_0_1, vec_-1_0_2, vec_-1_0_3, vec_0_0_-4, vec_0_0_-3, vec_0_0_-2, vec_0_0_-1, vec_0_0_0, vec_0_0_1, vec_0_0_2, vec_0_0_3, vec_1_0_-4, vec_1_0_-3, vec_1_0_-2, vec_1_0_-1, vec_1_0_0, vec_1_0_1, vec_1_0_2, vec_1_0_3, vec_2_0_-4, vec_2_0_-3, vec_2_0_-2, vec_2_0_-1, vec_2_0_0, vec_2_0_1, vec_2_0_2, vec_2_0_3, vec_3_0_-4, vec_3_0_-3, vec_3_0_-2, vec_3_0_-1, vec_3_0_0, vec_3_0_1, vec_3_0_2, vec_3_0_3 ),
(
  duplicate, bool_coerce,                 // 剩余偏移列表非空？
  (
    deconstruct,                          // rem → rest, offset
    num_2, fisherman/copy, add,           // target = pos + offset
    duplicate, type/to_item, string/iota, // target 的方块名
    ( str_矿石 ), num_0, index,           // 取“矿石”字面量
    index_of, num_0, greater_eq,          // 名称含“矿石”？
    (
      duplicate, break_block,             // 破坏方块（掉落物生成在该格）
      num_2, zone_entity/item,            // 该处半径 2 内的全部掉落物列表
      (
        duplicate, bool_coerce,           // 列表非空？
        (
          deconstruct,                    // 列表 → 剩余列表, 掉落物实体
          pickup_item,                    // 逐个拾取
          num_1, fisherman/copy, eval     // 继续处理剩余列表
        ),
        ( write/local, write/local ),     // 是 → 丢掉空列表与拾取循环体自身
        if, eval
      ),
      swap, num_1, fisherman/copy, eval   // 启动拾取循环
    ),
    ( write/local ),                      // 非矿石 → 丢弃 target
    if, eval,
    num_2, fisherman/copy, eval           // 递归处理 rest
  ),
  ( ),
  if, eval
),
rotate_reverse, num_2, fisherman/copy, eval,

// ── C. 哨卫步进到下一层                     栈：C', P, pos, empty
write/local,                             // 丢空列表
num_0, num_-1, num_0, construct_vec, add, // pos + (0,-1,0)
sentinel/create/great,                   // 以该点为新卓越哨卫（覆盖旧哨卫）
write/local                              // 丢 P，栈恢复为仅 C'
```

## 栈序说明

递归体 `P` 每一步的栈（自底向上）：

| 步骤 | 栈 |
| --- | --- |
| 进入 P | `C', P, pos, rem` |
| `duplicate, bool_coerce` | `C', P, pos, rem, bool` |
| `if, eval` | `C', P, pos, rem` |
| 真分支 `deconstruct` | `C', P, pos, rest, offset` |
| `num_2, fisherman/copy, add` | `C', P, pos, rest, target` |
| `... index_of, num_0, greater_eq` | `C', P, pos, rest, target, bool` |
| 非矿石分支 `( write/local ), if, eval` | `C', P, pos, rest` |
| 矿石分支 `duplicate, break_block` | `C', P, pos, rest, target` |
| `num_2, zone_entity/item` | `C', P, pos, rest, list` |
| `( Lb ), swap` | `C', P, pos, rest, Lb, list` |
| `num_1, fisherman/copy, eval`（进入拾取循环） | `C', P, pos, rest, Lb, list` |
| `duplicate, bool_coerce` | `C', P, pos, rest, Lb, list, bool` |
| `deconstruct, pickup_item` | `C', P, pos, rest, Lb, restOfList` |
| 列表耗尽 `( write/local, write/local ), if, eval` | `C', P, pos, rest` |
| `num_2, fisherman/copy, eval` | 以 `C', P, pos, rest` 再次执行 P |

收尾（C 段）：

| 步骤 | 栈 |
| --- | --- |
| 扫描结束 | `C', P, pos, empty` |
| `write/local` | `C', P, pos` |
| `num_0, num_-1, num_0, construct_vec, add` | `C', P, pos + (0,-1,0)` |
| `sentinel/create/great` | `C', P` |
| `write/local` | `C'` |

`fisherman/copy` 的深度：栈为 `C', P, pos, rest`（4 项）时，复制 `P`（下标 1）需要深度 `2`；栈为 `C', P, pos, rest, offset`（5 项）时，复制 `pos`（下标 2）也需要深度 `2`；拾取循环中栈为 `C', P, pos, rest, Lb, list`（6 项）时，复制 `Lb`（下标 4）需要深度 `1`。

## 注意事项

- **语言**：`string/iota` 取的是服务端语言下的名称。单人游戏会跟随客户端语言；专用服务器通常为 `en_us`，此时应把 `str_矿石` 改为 `str_Ore`。
- **字面量的位置**：`str_矿石` 是数据 iota，不能直接出现在代码里，因此写成 `( str_矿石 ), num_0, index`：先用括号转义成列表，再用 `index` 取出。
- **媒体消耗**：`sentinel/get_pos` 每次 1000（每周期调用两次，共 2000）；`sentinel/create/great` 每次 20000（哨卫步进每周期一次）；`break_block` 每次 1250（`cheap_to_break_block` 标签方块为 100）；`zone_entity/item` 不耗媒体；`pickup_item` 每个掉落物 100。
- **步进的代价**：每周期固定至少 22000 媒体（约 2.2 个紫水晶粉），20 tick 一轮即约 2.2 粉/秒。媒体不足时载荷中途 mishap，本轮不会走到 `hexcassettes:enqueue`，磁带循环自动停止。
- **步进不会自己停**：只要循环还在跑，哨卫就每周期下降一格，会一路降到世界底部甚至穿过基岩（`sentinel/create/great` 只校验施法范围，不校验方块）。需要手动停止时取出磁带/切断红石，或另用 `sentinel/destroy` 清除哨卫。
- **步进始终合法**：新哨卫点距旧哨卫仅 1 格，落在卓越哨卫半径（默认 16）内，因此无需玩家靠近。
- **拾取对象**：挖掘掉落物名称（粗铁、煤炭、钻石等）**不含“矿石”**，不能按名称过滤；这里改为按位置 `zone_entity/item`（半径 2）取该处附近全部掉落物并逐个拾取。半径 2 覆盖了“查询点与方块中心最多差 1.3 格”的最坏情况（`x/z` 0.5 + 散布 0.25、`y` 0.5 + 散布 0.25）。
- **拾取的副作用**：半径 2 内的其它掉落物（相邻格、玩家之前掉落的物品）也会被一并拾起；背包放不下时 `playerTouch` 只收一部分，剩余仍留在地上（原版行为）。`pickup_item` 会忽略物品的拾取延迟。
- **不破坏也不报错**：`break_block` 对空气、基岩、工具等级不足只会不破坏（仍扣媒体），不会中断咒术；但若目标格无编辑权限（领地、出生点保护等），`assertPosInRangeForEditing` 会 mishap 并终止整轮循环。
- **跨维度哨卫**：若玩家哨卫在其它维度，`sentinel/get_pos` 会 mishap，整轮失效。
- **范围对齐**：`x/z ∈ [-4, 3]` 是以哨卫“脚下那一格”为基准的 8×8；若想改成以方块中心对称的 `[-3, 4]` 或其它偏移，只需替换偏移表里的 64 个 `vec_...`（注意 `y` 分量保持 0）。
